# 6. Requirements specification

Приоритеты: M = must, S = should, C = could. Числовые пороги качества (отмечены `[T]`) фиксируются в этом файле коммитом **после EDA и до начала экспериментов**, чтобы не подгонять критерии под результат.

## Функциональные требования
| ID | Требование | Приоритет | Критерий приёмки |
|---|---|---|---|
| FR-01 | Загрузка MODIS NDVI/EVI и погодных данных по областям за выбранный период | M | Скрипт воспроизводимо создаёт таблицу область×16-дневное окно×показатель; пропуски отмечены; лог фиксирует дату и источник |
| FR-02 | Загрузка и парсинг таблиц Бюро статистики (урожайность, площади, погибшие посевы) | M | Парсер читает файлы всех лет, «х» и «-» превращаются в пропуски, области приведены к единой схеме; тесты на реальных файлах проходят |
| FR-03 | Вычисление признаков по фенофазам (NDVI, осадки, температура, VCI, SPI) | M | Признаки года N не используют данные урожая года N; тест на отсутствие утечки |
| FR-04 | Прогноз урожайности яровой пшеницы по области на фиксированные сроки до уборки | M | Для каждого срока есть RMSE/MAE; модель лучше baseline B1 по RMSE `[T]` |
| FR-05 | Оценка уровня риска засухи (норма/внимание/риск/критично) | M | Определение уровня документировано; измеряются recall, ложные тревоги, заблаговременность в неделях `[T]` |
| FR-06 | Карта областей и дашборд: выбор области и срока, сезон против нормы | M | Пользователь получает риск и прогноз по любой области не более чем за 3 действия |
| FR-07 | Объяснение результата (SHAP, сравнение сезона с засушливыми годами) | M | Для каждой области доступно объяснение вклада признаков |
| FR-08 | Ретроспективный просмотр прошлого года на выбранную дату | S | Для любого года система показывает прогноз, который был бы получен на дату |
| FR-09 | Сравнение моделей в интерфейсе | C | Таблица метрик моделей доступна на странице |
| FR-10 | Экспорт отчёта по области (CSV/PDF) | C | Файл скачивается и содержит прогноз, уровень риска, источники |

## Нефункциональные требования
| ID | Требование | Приоритет | Критерий приёмки |
|---|---|---|---|
| NFR-01 | Воспроизводимость: результат пересобирается из исходных данных одной командой | M | `make data && make train` на чистом окружении даёт те же метрики (с фиксированным сидом) |
| NFR-02 | Честная валидация: разбиение только по годам, дополнительно по регионам | M | Описано в плане верификации; тесты проверяют разбиение |
| NFR-03 | Прозрачность источников: у каждого значения в интерфейсе источник и дата обновления | M | Проверка интерфейса по чек-листу |
| NFR-04 | Производительность: страница карты загружается за `[T]` секунд на предрасчитанных данных | S | Замер на тестовой машине |
| NFR-05 | Данные: только открытые агрегированные, без персональной информации | M | Ревью репозитория; `.gitignore` и отсутствие секретов |
| NFR-06 | Адаптивный интерфейс (читается на телефоне) | S | Проверка на ширине 375 px |
| NFR-07 | Документированность: README и описание запуска | M | Новый человек запускает проект по инструкции |
