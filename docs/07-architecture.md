# 7. Architecture and diagrams

Исходники диаграмм (Mermaid) лежат в `docs/diagrams/`; GitHub и GitLab отображают их автоматически.

## Системный контекст
См. `diagrams/context.mmd`: три роли пользователей и два внешних источника данных (Google Earth Engine, Бюро национальной статистики).

## Варианты использования
См. `diagrams/usecase.mmd`: аналитик (риск, прогноз, объяснение, ретроспектива, отчёт), эксперт (метрики и ошибки), администратор (обновление данных, переобучение).

## Компоненты (черновик)
См. `diagrams/components.mmd`.

| Компонент | Ответственность | Требования |
|---|---|---|
| Ingestion | выгрузка рядов из GEE, парсинг xlsx Бюро, нормализация областей | FR-01, FR-02 |
| Хранилище | Parquet/GeoPackage, версии выгрузок | NFR-01, NFR-05 |
| Features | признаки по фенофазам без утечки | FR-03 |
| Models | baseline и ML-модели | FR-04, FR-05 |
| Evaluation | валидация по годам и регионам, метрики | NFR-02 |
| Explainability | SHAP, сравнение с засушливыми годами | FR-07 |
| API | выдача предрасчётов | FR-06 |
| Dashboard | карта, прогноз, риск, объяснение, ретроспектива | FR-06, FR-08 |

## Данные
Основные сущности: `region`, `year`, `window` (16-дневное окно), `observation` (NDVI/EVI/осадки/температура), `yield_stat` (урожайность, площадь, погибшие посевы), `forecast` (область, год, срок, значение, интервал), `risk` (область, год, срок, уровень, вклад признаков).

## Сценарий данных
Пакетный пайплайн раз в 16 дней и раз в год после публикации статистики обновляет выгрузки, пересчитывает признаки и предрасчёты; API и дашборд читают готовые файлы.

## Согласованность
Каждое функциональное требование отображено на компонент (таблица выше); каждая роль из диаграммы использования соответствует требованию из `06-requirements.md`.
