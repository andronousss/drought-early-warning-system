# 5. Technology comparison

Критерии выбора определяются требованиями ([06-requirements.md](06-requirements.md)): воспроизводимость, малая команда и срок, открытые данные, отсутствие GPU, простая демонстрация.

## Решение 1. Доступ к спутниковым и погодным данным
| Вариант | Плюсы | Минусы | Оценка |
|---|---|---|---|
| **Google Earth Engine** | готовые коллекции MODIS/ERA5/CHIRPS, агрегация по областям в облаке, нет больших загрузок | регистрация, внешняя зависимость, условия для некоммерческого использования | **выбран** |
| Copernicus Data Space + openEO | официальный источник Sentinel-2, открытый | сложнее настройка, больше обработки | резерв для уровня районов |
| Скачивание с NASA + GDAL/rasterio | полный контроль | большие объёмы, много инженерной работы | отклонён (срок) |

Смягчение риска: выгрузки сохраняются в `data/raw/`, повторные запросы не требуются.

## Решение 2. Модели
| Вариант | Плюсы | Минусы | Роль |
|---|---|---|---|
| Базовые (среднее, тренд, пик NDVI) | прозрачны | грубы | обязательный baseline |
| Ridge/Lasso, случайный лес, LightGBM | надёжны на малых выборках, объяснимы (SHAP) | ограниченная работа с последовательностями | **основные модели** |
| 1D-CNN/LSTM | учитывают временную структуру | риск переобучения на малой выборке | эксперимент |

## Решение 3. Хранение и интерфейс
| Слой | Выбран | Альтернативы | Обоснование |
|---|---|---|---|
| Хранение | Parquet + GeoPackage | PostgreSQL/PostGIS, DuckDB | десятки областей и годы, база избыточна |
| API | FastAPI | Flask, без API | типизированные схемы, автодокументация |
| Интерфейс | Streamlit (веб) | Leaflet/MapLibre, Flutter Web | быстрее всего даёт карту и графики на Python; пользователи работают на компьютере |

## Способ взаимодействия компонентов
Пакетный пайплайн (ingestion → features → models) пишет предрасчёты в файлы; API и дашборд только читают их. Это упрощает тесты и воспроизводимость.
