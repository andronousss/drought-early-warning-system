# 9. Verification and evaluation plan

## Что доказываем
Модель заранее обнаруживает засуху и прогнозирует урожайность точнее простых базовых методов и честно сообщает об ограничениях.

## Метки засухи (фиксируются до экспериментов)
| Метка | Определение | Источник |
|---|---|---|
| D1 | аномалия урожайности: ниже линейного тренда области более чем на k·σ (k выбирается один раз после EDA) | Том III |
| D2 | доля погибших посевов яровых к посеву, выше порога `[T]` | Том I, лист 6.1 и площади посева |
| D3 | метеорологическая засуха: SPI ниже порога за вегетацию | CHIRPS/ERA5-Land |
Результат оценивается по каждой метке отдельно, а также по согласованному событию (D1 и один из D2/D3).

## Baseline
| ID | Метод |
|---|---|
| B0 | среднее урожайности области за прошлые годы |
| B1 | линейный тренд по области |
| B2 | регрессия по пиковому NDVI |
| B3 | правило по классическим индексам (VCI/SPI с порогом) для риска |

## Модели
M1 Ridge/Lasso, M2 LightGBM, M3 случайный лес, M4 1D-CNN/LSTM (опционально).

## Условия измерения
- Основная валидация: leave-one-year-out; дополнительная: пространственные блоки (перенос между регионами).
- Тренд урожайности вычисляется только по прошлым годам относительно проверяемого.
- Сроки прогноза: 1 июня, 1 июля, 15 июля, 1 августа.
- Фиксированные сиды, версии библиотек и данных записываются вместе с результатом.

## Метрики
- Урожайность: RMSE, MAE, R², относительная ошибка; отдельно по засушливым годам.
- Риск: recall засух, доля ложных тревог, precision, **заблаговременность** (недели между сигналом и уборкой).
- Устойчивость: доверительные интервалы (бутстреп по годам).

## План тестирования
| Тип | Что проверяем |
|---|---|
| Unit | парсеры xlsx (на реальных файлах разных лет), нормализация областей, обработка «х» и «-» |
| Данные | диапазоны значений, отсутствие дублей и пропущенных областей |
| Утечка | признаки года N не используют информацию года N после срока прогноза |
| Интеграция | пайплайн от выгрузки до предрасчётов на тестовом наборе |
| Интерфейс | сценарии A-C из `08-ux-prototype.md`, адаптивность 375 px |

## Критерии успеха
Фиксируются в `06-requirements.md` как `[T]` до экспериментов. Отрицательный результат (модель не лучше baseline) допустим и описывается честно.
